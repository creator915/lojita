# 复位（2026-10-22 晚）：从 subagent 递归到"一切皆文件"的范畴数据库

一句话：旧基础是**父程序开孩子、等孩子回来、拿返回值**（DeepSeek Harness 的 suspending 调度）；新基础是**文件库 + 触发器**（restarting）：
每个文件上挂着 memory 与权限，特定的行被写就唤起该文件的 agent 跑一轮，agent 之间只有行（协议），没有调用（继承）。
本页四件事：旧的那一套在哪、已经清掉什么、留下什么、新基础是什么（标 ❓ 的要你拍板）。

```
 旧（10-11 → 10-22 上午）                          新（10-22 晚起）
 父 agent 的程序                                   文件库（Store）
   ├─ enter 孩子（配额对半、realm 收窄）             p/spec/*  ──写──▶ 唤起 p.agent 跑一轮 ──写──▶ p/result
   ├─ 就地跑孩子的程序                                                                            │
   ├─ leave，拿孩子的 Result（返回值）              p/kids/K/spec/* ◀─ p.agent 写 ─┐           唤起 p 的父
   └─ 续体里接着干                                   K.agent 被唤起 ─▶ K/result ────┴─▶ 唤起 p.agent
 memory 一半在栈帧（父的上下文）里                   memory 全在行里；没有栈，没有返回值
 调度 = 程序的控制流                                 调度 = 一个查询（谁被唤起）+ 一个循环（操作系统，不是 agent）
```

## 四、新基础

### 4.1 三张表

```
 文件行     p 的属性：spec（父写）、code（经搬运）、refute、memo、verdict、result、quota、dropped      01-objects §1 不变
 关系表     holds（p → p/kids/K）、imports（X → E₀ 或孩子）、test-of、refutes、spec-of                01-objects §2 不变
 agent 文件 每个计算文件 p 配一个 p.agent = (memory , 权限)
              memory = p 下的行（spec、trace、memo、verdict、result）——不在别处
              权限   = 静态表：(文件 , 操作类型 , 键的形状)，见 4.5
```

一个 agent 没有自己的状态；"换一个 LLM、换一个进程续跑同一个节点"= 再跑一轮，读同一些行。这一条 02-agents §2.1 说过，现在是全部，不是一半。

### 4.2 Σ 是一个目录：文件 × 四类操作

```
 文件           open                        close    read                       write
 store/<p>      （权限是静态的，不开）        —        get k、Query（k 在 p 下）   setN（Note 键）、transport（code/、kids/K/spec/）
 agda           enter h：开一个检查器会话     leave    Verdict                    checkAt h k
                （可见模块 + flag）
 llm            挂载即开                     —        答卷（文件名表）            ask（Query）
 human          挂载即开（只有根会话有）     —        回答                       ask
 sh、eval、编辑器三步                        不在文件 agent 的目录里；根会话 / 壳才有
```

与旧 Σ 的差别只有一处：`enter` / `leave` 只开关**检查器会话**（Env：这一组 check 看得见谁、开什么 flag），不带配额、不带 realm、不开孩子。
沙箱帧（E₀⁻）与粘合帧（E₀，加 `--safe`）照旧是它的两种用法。10-files-resources §3 说"enter 同时开了两个文件，v1 做成一步"，现在拆开：子文件系统靠静态权限，子进程靠触发器。

### 4.3 触发器 = 一个查询（"在特定条件下唤起 agent"）

```
 唤起 p.agent 的条件（调度器每轮算一次；它是对 Store 的一个查询，不存）
   p/spec/stub 与 p/spec/test 存在                              有任务
   ∧ p/dropped 不存在                                          没被搬到 1
   ∧ #(p/trace/*/prompt) < p/quota                              还有预算
   ∧ ( p/result 不存在  ∨  p/result 记的 spec 哈希 ≠ 现在 p/spec 的哈希 )     没结局，或结局已过期（spec 改了）
   ∧ 对 p 持有的每个孩子 K：K/result 存在且其哈希 = K/spec 的哈希，或 K/dropped 存在     孩子都回来了（否则等）
 唤起根会话的条件
   <R>/result 出现或变化
 没有任何 agent 可唤起、根会话也不等 ⇒ 一局结束
```

协议 = 谁写哪行、唤起谁：

| 写的行 | 谁写 | 唤起谁 | 含义（四类操作） |
| --- | --- | --- | --- |
| `p/kids/K/spec/*`、`p/kids/K/quota` | p.agent（transport whole / setN） | K.agent | "这是你的 spec 和预算"：父对 K 的 **open** |
| `p/kids/K/result` | K.agent | p.agent | "我回来了：solved / refuted"：K 的 **close** |
| `p/kids/K/dropped` | p.agent | 谁也不（K 不再满足条件） | 搬到 1：父对 K 的 close |
| `<R>/spec/*`、`<R>/quota`、`session/<R>/n` | 根会话 | R.agent | 开局 |
| `<R>/result` | R.agent | 根会话 | 结局 |
| `p/verdict/n`、`p/memo/n` | p.agent 自己 | p.agent（条件仍满足就再来一轮） | 自我重试；"让出之前把学到的写成行" |
| `p/result = exhausted` | **调度器**（预算用完、无结局） | p 的父 | 预算耗尽是调度器状态，不是判决（10-21 已定） |

**一条原则怎么落地**："被依赖的接口动了，依赖它的跟着动；接口没动，链到此终止"= 触发条件里那个哈希比较。
父改设计时对每个孩子重写 spec：文本相同 ⇒ 哈希相同 ⇒ K/result 仍有效 ⇒ K 不被唤起（keep）；文本变了 ⇒ K 的结局过期 ⇒ K 被唤起（重做）；答卷里没有了的孩子 ⇒ dropped。
keep 不再是父程序里的 `compareKids`，是触发器的一条比较。这和 01-objects §6"iface 哈希决定 keep"、store-relations §三"verdict 行记依赖的哈希"是同一件事。

### 4.4 一轮（turn）长什么样

沿用归档 `Node.agda` 的单轮内容，去掉所有递归：

```
 被唤起 ─▶ 看自己的行：有孩子的 result 吗？
   没有孩子的 result（第一轮或重试）：
     ask（Query：spec 两段 + 规则 + 上次的 verdict / memo）→ 答卷落 draft/<step>/ → 分类
       解答   fill 两段 → 沙箱 check（E₀⁻）→ 粘合 check（E₀，--safe）→ 过：写 result = solved …@hash；没过：verdict、memo
       分解   whole 每个孩子的两段 stub 到 kids/K/spec/、setN kids/K/quota → whole 根正文、fill 根测试 → 洞阶段沙箱 check
              → 过：**轮结束**（孩子们因 spec 被写而被唤起；父等 result）；没过：verdict、memo
       反驳   whole 到 code/XRefute.agda → audit → 沙箱 check → 过：result = refuted …；没过：verdict、memo
       不合格 verdict、memo
   孩子的 result 都在：
     全 solved → 粘合 check（孩子清单 + 自己两段）→ result = solved；没过 → 改设计
     有 refuted / exhausted → 改设计：memo 记原因，ask（promptRedesign：当前根正文 + 孩子的反驳原文）→ 分类
       design：对每个孩子 whole 两段（哈希相同的自然 keep，见 4.3）、不在答卷里的写 dropped、根 whole / fill、洞阶段沙箱 → 轮结束
       solution / refute / malformed：同上
 轮结束 = 程序 done；下一轮由触发器决定
```

一轮最多 ask 一次（预算按轮数），这就是 I8。"父只多一步记忆"（A7）自动成立：父的 memo 在孩子回来后恰多一行（改设计那一行）。
"父不读孩子的 code"（A6）由 4.5 的权限表给，不靠约定。

### 4.5 权限是静态的类型，不是栈帧

```
 module Agent (p : Path) …           p 是模块参数；程序能造的键全是 p ++ …，证明用 prefix-++
 能写  p/memo/n  p/verdict/n  p/result                         setN（Note）
       p/code/X.agda  p/code/XTest.agda  p/code/XRefute.agda   transport fill / whole
       p/kids/K/spec/stub  p/kids/K/spec/test                   transport whole
       p/kids/K/quota  p/kids/K/dropped                         setN
 能读  p/spec/*  p/draft/*  p/memo/*  p/verdict/*               row / last / get
       p/kids/K/result  p/kids/K/spec/*  p/kids/K/code/KRefute.agda   改设计要看孩子的结局与反驳
 不能  p/kids/K/code/K.agda、K 的 trace / memo；父、兄弟的任何行；自己的 spec    → Σ 里没有能造这些键的构造子
 检查器 checkAt h k：k 可以是孩子的 code（让检查器读），agent 自己拿不到文本
```

这正是归档 `Node.agda` §2 `NodeSig` 的做法（工具注册表 = 一个 `Op` 类型），对的，保留；只是 realm 不再从父的栈帧继承，而是模块参数。
`Env.set` 的 `isPrefix (realmOf ix) k` 前置条件由此消失：realm 不是运行时的量。

### 4.6 调度器是操作系统，不是 agent

```
 Agda 玩具（refl 用）   sched fuel board：算唤起集（4.3 的查询，对 S.Board 是纯函数）→ 按路径序取第一个 p → 跑 turn p → 重复
                        棋谱是平的：一轮接一轮，每轮标 p；没有嵌套 enter
 后端                   同一个循环；并发 = 唤起集里前缀不交的两个文件可同时跑（Store.fill-indep 说它们的事务可换）
 "B 中途被杀"           父写了 B/dropped 之后 B 这一轮再写的行都够不到根 = 垃圾；不需要真的杀进程，要杀也只是 close 一个文件
 一局结束               唤起集为空且根会话不等
```

02-agents §1 说"没有调度器 agent"——仍然对：调度器没有 memory、不问 LLM、不写 memo，它是内核 / cron，是"一切皆文件"里的进程表。

### 4.7 根会话

挂在根 `[]` 上的 agent：ask 挂到人（信箱文件）或人 + LLM；一轮 = 写 `<R>/spec/*`、`<R>/quota`、`session/<R>/n`，然后等；`<R>/result` 出现就被唤起，读它、告诉人。
它的 memory = `session/` 行。"一个会话 = 一个根 = 一个 store 目录"不变（08 §5）。M2 计划里 `Boot.agda` 的常量版，就是根会话第一轮的脚本。

### 4.8 ❓ 待你拍板（D0 讨论的议程）

1. **keep 的判法**：唤起条件里比 spec 哈希（推荐：和 Rebuilder 的 verifying trace 是同一个机制），还是"写相同值不落行"由 Store 保证。
2. **孩子的预算**：父写 `K/quota`——由 LLM 在答卷里给、固定对半、还是根会话给总额由调度器均分。
3. **调度循环放哪**：Agda 的 `Run` 程序（推荐：后端仍只是余模型，玩具与真跑同一份代码），还是后端 Haskell 里。
4. **检查器会话**：保留 `enter h` / `leave` 两个名字只管 Env（推荐），还是改叫 openChecker / closeChecker。
5. **根会话的 ask 挂什么**：人（信箱文件）/ 人 + LLM；Boot 常量版算不算它的第一轮。
6. **并发**：第一版顺序（一次一轮），后端触发循环时再开并发；"杀 B"= dropped 行，不真杀——确认。
7. **docs/harness/ 怎么处理**：按本页重写成新的一夹（推荐：01、10 的内容大部分搬过去），还是在原页上改。
